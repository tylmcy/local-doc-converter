# LocalDoc Forge 作品集展示改版设计

**日期：** 2026-10-06

**状态：** 已批准，实施中

## 1. 目标与背景

项目已发布 `v2.0.0`，具备 TXT、Markdown、DOCX 六条互转路径及 PDF → TXT，但 GitHub 首屏仍以功能清单为主，缺少鲜明名称、真实界面、演示流程和可快速理解的工程亮点。本次将展示名统一为 **LocalDoc Forge｜本地文档工坊**，在不改变转换行为的前提下，把仓库整理成清晰、可信的作品集案例。

推荐标语为：**离线、可解释、批量的文档转换与 PDF 文本提取。**

## 2. 范围

### 2.1 包含

- 制作可在 GitHub README 直接显示的代码原生 SVG 横幅。
- 使用本地真实 Streamlit 页面制作至少两张截图：主界面、转换完成后的结果与报告。
- 重构 README 首屏与内容顺序，突出隐私边界、七条转换路径、批处理、安全预检、PDF OCR 回退、93.14% 固定旧印刷体基准和 123 项测试。
- 增加一段从上传到 ZIP 下载的演示流程，并保留必要的安装、使用、限制和验证细节。
- 使用 Mermaid 更新架构图，不依赖外部图片托管。
- 将 GitHub 仓库简介改为与 V2 行为一致的简短文案，并补充 `pdf-to-text`、`ocr`、`paddleocr`、`local-first`、`privacy` 等 Topics。
- 保持当前仓库 URL、公开可见性、版本标签、Release 和 Issue 不变。

### 2.2 不包含

- 不修改转换核心、网页交互逻辑、依赖或版本号。
- 不制作安装包、官网、宣传视频或人工伪造的产品画面。
- 不使用第三方真实 PDF、人工转写、模型目录或本机隐私文件作为公开素材。
- 不重命名 GitHub 仓库 `local-doc-converter`。
- 不移动或重写 `v2.0.0` 标签与 Release。

## 3. 展示与视觉决策

### 3.1 名称层级

- 英文主品牌：`LocalDoc Forge`
- 中文辅助名：`本地文档工坊`
- 功能说明：`Local-first document conversion & PDF text extraction`
- Python 包名、CLI 命令与仓库 slug 保持现状，避免兼容性和链接迁移。

### 3.2 横幅

横幅采用深色纸张/文档主题，使用 SVG 的几何图形、渐变和文字排版，不引用网络字体或外部素材。必须在浅色与深色 GitHub 页面中都保持足够对比度，不宣称不存在的功能。

### 3.3 截图

- 截图只包含仓库自制演示文件和安全的本地输出路径。
- 主界面截图展示品牌、离线状态、文件上传、目标格式和输出目录。
- 结果截图展示批量成功指标、ZIP 下载、结构统计和 PDF 逐页报告。
- 截图裁去浏览器个人信息、系统菜单栏、用户名和无关窗口。
- 若当前界面无法自然显示新品牌，可只为展示名称做最小文案同步；这不改变功能行为。

## 4. README 信息架构

README 依次呈现：

1. 横幅、品牌名、标语、状态徽章。
2. 三项核心卖点：完全本地、批量互转、PDF 原生/OCR 双路径。
3. 真实界面截图。
4. 支持格式矩阵与一分钟演示流程。
5. 可复核数据：123 项测试、九份固定 PDF、93.14% 固定旧印刷体基准。
6. 快速开始。
7. 详细安装、OCR 准备、CLI、架构、报告、安全边界与已知限制。
8. 项目结构、设计与验证资料链接、许可证。

数据必须保留适用范围，不能把固定五页 93.14% 外推为通用 OCR 准确率。

## 5. 文件影响

- `README.md`：重组首屏和章节顺序，保留必要的完整说明。
- `app.py`：仅同步展示名称与页面标题，不改变交互和转换逻辑。
- `docs/assets/localdoc-forge-hero.svg`：新增横幅。
- `docs/assets/localdoc-forge-home.png`：新增真实主界面截图。
- `docs/assets/localdoc-forge-results.png`：新增真实结果截图。
- `docs/designs/2026-10-06-portfolio-presentation.md`：本设计记录。
- GitHub 仓库元数据：更新 description 与 topics；不改仓库名和 URL。

如果实际截图需要临时输出，临时目录不得提交；最终只提交经过隐私检查的展示图片。

## 6. 风险控制

- **截图泄露路径或隐私：** 使用项目自制样例和专用展示输出目录，提交前以 OCR/人工双重检查可见文字。
- **视觉大于事实：** 所有数字均链接到现有验证文档，不增加无法复核的宣传语。
- **README 过长：** 首屏先给结论和快速开始，详细技术说明后置，但不删除安全边界与限制。
- **品牌与兼容标识混淆：** 只改展示名；Python 包、CLI、目录名和仓库 slug 保持不变。
- **外部链接失效：** 横幅与截图存储在仓库内，README 使用相对路径。

## 7. 验证策略

- 启动 Streamlit，确认新名称与现有功能正常显示。
- 使用项目自制/现有演示输入完成一次真实批量转换并拍摄结果。
- 检查图片尺寸、清晰度、文件大小、透明度和浅/深背景可读性。
- 搜索截图及提交文件中的用户名、绝对路径、邮箱、密钥和第三方受限材料。
- 运行 `pytest`、`openspec validate --specs`、`git diff --check`。
- 在 GitHub 渲染后检查 README 图片、Mermaid、链接、仓库描述和 Topics。

## 8. 验收标准

- GitHub 首屏在无需滚动太远的情况下明确说明“是什么、为什么可信、如何运行”。
- 两张截图均来自真实运行且无隐私信息。
- 名称统一为 **LocalDoc Forge｜本地文档工坊**，旧包名和 CLI 兼容。
- 公开描述准确包含离线、批量、TXT/Markdown/DOCX、PDF → TXT/OCR。
- `v2.0.0` 标签与 Release 指向保持不变，CI 继续通过。
