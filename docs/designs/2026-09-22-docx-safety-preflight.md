# DOCX 安全预检设计文档

**日期：** 2026-09-22

## 目标

在 DOCX 交给 Pandoc 之前进行只读、离线的 ZIP 容器安全预检，阻止异常压缩、路径穿越、符号链接、加密条目和损坏容器导致的资源耗尽或越界文件访问，同时尽量不影响普通 Word 文档。

## 背景与约束

- DOCX 本质是 ZIP 容器，现有 50 MB 限制只约束压缩后大小，不能限制解压后的体积。
- 项目面向 MacBook Air M5 本地运行，需要兼顾安全性、转换速度和对常见 Word 文档的兼容性。
- Pandoc 继续负责 DOCX 语义解析；本项目不自行实现 DOCX XML 解析器。
- 预检必须完全离线，不能提取文件到磁盘，也不能修改输入文件。
- pytest 依赖版本不在本次改动范围内。

## 范围

### 包含

- 校验 DOCX 是否为有效 ZIP，且包含最基本的 DOCX 结构文件。
- 校验 ZIP 条目名称、条目数量、单条目大小、总解压大小和压缩比。
- 拒绝加密条目、符号链接、路径穿越和损坏的 CRC。
- 流式读取条目，核对实际解压字节数，不将内容整体加载到内存。
- 识别宏、OLE 嵌入对象和外部关系并写入转换警告。
- 在网页、CLI 和 JSON 报告中返回可理解的中文错误。

### 不包含

- 病毒、木马或恶意宏内容扫描。
- 对 Word XML 语义和版式进行完整验证。
- 自动删除宏、OLE 对象或外部链接。
- 取代 Pandoc 或实现新的 DOCX Reader。

## 设计

### 架构

新增独立的 `docx_safety` 模块。单文件转换器识别到 DOCX 输入并确认目标格式有效后，先调用预检，再调用 Pandoc：

```text
DOCX 输入
  → 压缩文件大小检查
  → DOCX ZIP 安全预检
     → 容器与必需条目检查
     → 路径、加密和符号链接检查
     → 声明大小与压缩比检查
     → 流式解压、实际大小与 CRC 检查
     → 收集宏/OLE/外部关系警告
  → Pandoc Reader
  → 原有转换流程
```

### 组件

#### `DocxSafetyLimits`

- 责任：集中描述预检阈值，允许测试使用较小阈值，无需制造超大测试文件。
- 默认值：
  - 最多 5,000 个 ZIP 条目；
  - 解压总大小最多 500 MB；
  - 单个条目最多 100 MB；
  - 总压缩比最多 200 倍；
  - 单条目压缩比最多 1,000 倍。

#### `inspect_docx(path, limits)`

- 责任：只读检查 DOCX 容器，成功时返回条目数、实际解压总量和警告。
- 输入：DOCX 路径与可选阈值。
- 输出：不可变的 `DocxInspection`。
- 失败：抛出已有的 `ValidationError`，由转换器写入单文件报告，不中断同批其他文件。
- 依赖：仅使用 Python 标准库 `zipfile`、`stat`、`pathlib` 和 `re`。

#### 转换器集成

- 仅对源格式为 DOCX 的输入执行预检。
- 同格式跳过仍沿用现有行为，不进行无意义解析。
- 预检警告追加到现有 `report.warnings`，不改变报告数据结构。

### 校验规则

1. 文件必须能被 `zipfile` 识别并打开。
2. 必须包含 `[Content_Types].xml` 和 `word/document.xml`。
3. ZIP 条目名不得为空、包含空字节、反斜杠、绝对路径、Windows 盘符或 `..` 路径段。
4. ZIP 条目不得使用加密标记，不得声明为 Unix 符号链接。
5. 中央目录声明的条目数、大小和压缩比必须在阈值内。
6. 所有普通文件以固定大小分块流式读取；实际读取量再次受单条目和总量阈值约束。
7. 完整读取触发 `zipfile` 的 CRC 校验；损坏内容转为可理解的校验失败。
8. 检测到 `vbaProject.bin`、`word/embeddings/` 或关系文件中的 `TargetMode="External"` 时只产生警告，因为 Pandoc 不会执行宏或 OLE 对象，直接拒绝会增加正常文档误报。

### 错误处理

- 非 ZIP、缺少必需结构、路径异常、超限、加密、符号链接、CRC 损坏：拒绝转换并写入失败报告。
- 宏、OLE、外部关系：允许继续转换，报告提示这些内容可能被忽略或不会被主动访问。
- 文件系统读取错误：沿用转换器的 `OSError` 处理路径。
- 预检不创建临时文件，因此失败时没有额外清理工作。

## 测试策略

- 正常最小 DOCX 通过，并正确返回条目数和解压量。
- 非 ZIP、缺少必需条目和损坏 CRC 被拒绝。
- `../`、绝对路径、反斜杠、Windows 盘符和符号链接被拒绝。
- 使用注入的小阈值测试条目数量、单条目大小、总大小、单条目压缩比和总压缩比。
- 宏、OLE 嵌入对象和外部关系产生去重警告但不阻断。
- 转换器在预检失败时生成失败报告，不调用 Pandoc Reader，不产生输出文件。
- 运行全部 pytest 和六路径真实 Pandoc 集成测试，确保现有功能无回归。

## 已确认决策

- 采用上述默认阈值。
- 异常容器直接拒绝，潜在活动内容只警告。
- 不引入新依赖，不升级 pytest。
- 用户已明确要求设计完成后按本方案直接实施，无待确认问题。
