# v2 路线规划：PDF → TXT 专项

**日期：** 2026-09-22

**状态：** `v2.0.0` 已于 2026-09-24 发布；本文保留规划过程，最终验收以 OpenSpec 主规格、归档任务和发布说明为准
**基线版本：** `v1.0.1`

## 1. 目标与范围

v2 当前阶段只专注把 PDF → TXT 做好，不同时推进安装包、Android、HTML 或其他新格式。

已确认的范围取舍：

- 暂不支持 RTF、ODT、EPUB。
- PDF → TXT 是当前唯一核心能力；不再开发 PDF → DOCX，移动端以后重新评估。
- HTML 保留在后续候选列表，但不进入当前里程碑。
- macOS 打包和 Android 应用全部暂缓，等 PDF → TXT 的质量和使用流程稳定后再重新规划。
- 继续坚持完全本地离线，不调用 AI API、云服务或在线 OCR。

## 2. PDF 转换的质量边界

PDF 是“固定页面描述”，不是带完整语义的编辑文档。标题、段落、表格、阅读顺序、页眉页脚通常没有明确标记。因此，“做好”应定义为高质量、可解释的结构恢复，而不是承诺任意 PDF 像素级还原为 Word。

### 2.1 可以重点做好的内容

- 正常文本型 PDF 的中文、英文和数字提取。
- 单栏和常见双栏页面的阅读顺序恢复。
- 跨行段落合并、断词处理、重复页眉页脚和页码清理。
- 根据字号、字体、位置和间距推断标题层级。
- 常见编号列表、项目符号列表和简单表格恢复。
- 对图片中的文字进行 OCR；普通插图不写入 TXT，但在报告中统计并说明丢失。
- 扫描 PDF 通过本地 OCR 获取文本，并在报告中标注 OCR 页及低置信度风险。

### 2.2 不承诺的内容

- 任意复杂 PDF 与原版完全一致的字体、字距、分页和坐标布局。
- 极复杂表格、跨页表格、数学公式、文本框、印章、手写内容的无损恢复。
- 模糊、倾斜、低分辨率扫描件达到高质量原生 PDF 的识别效果。
- 对加密、损坏、恶意构造或超出资源限制的 PDF 强行转换。

### 2.3 TXT 输出策略

PDF → TXT 以“阅读顺序正确、文字干净”为首要目标。标题、段落和列表使用空行、缩进和原有编号表达；表格优先输出为制表符分隔的文本，无法稳定恢复时按阅读顺序降级，并在报告中说明。TXT 无法保存图片和精确页面布局，这属于格式本身的限制。

## 3. 桌面版技术方案

Pandoc 没有 PDF Reader，PDF 输入不能沿用现有的 Pandoc 直接读取路径。推荐先把 PDF 恢复成统一语义块，再交给专用的纯文本渲染器；不为单一的 PDF → TXT 路径强行依赖 Pandoc AST。

```text
PDF 输入
  → 安全预检
  → 逐页分类（文本型 / 扫描型 / 混合型）
  → 文本型页面：字符、坐标、字体、图片、表格提取
  → 扫描型页面：离线 OCR，再提取文字与坐标
  → 页面布局与阅读顺序恢复
  → 标题、段落、列表、表格语义块与图片统计
  → 统一语义块
  → 纯文本渲染与清理
  → TXT
  → 转换报告
```

### 3.1 依赖选择

| 用途 | 首选 | 原因 |
|---|---|---|
| PDF 元数据与基础文本 | `pypdf` | 纯 Python、许可证友好，可做基础检测与降级提取 |
| 坐标、字符、图片和表格分析 | `pdfplumber` | MIT 许可证，提供字符/单词坐标和表格接口，适合文本型 PDF |
| PDF 页面渲染 | `pypdfium2`（技术验证后锁定） | 把扫描页安全地渲染为 OCR 输入，不依赖在线服务 |
| 扫描件主 OCR | PaddleOCR PP-OCRv5 mobile 检测与识别模型 | Apache 2.0，中文、英文、旋转和复杂文字场景能力较强，返回文字框和置信度 |

暂不默认采用 PyMuPDF。其能力较强，但开源许可证为 AGPL；当前仓库使用 MIT，直接集成会带来许可证兼容和分发义务风险。除非以后明确调整许可证或购买商业许可，否则优先使用 `pypdf` 与 `pdfplumber`。

OCRmyPDF 更适合给 PDF 添加可搜索文字层；当前最终产物只有 TXT，因此不把它作为主 OCR 流程。扫描页将直接渲染后交给 PaddleOCR，减少生成中间 PDF 的成本。PaddleOCR 模型在首次安装/初始化时准备到本地，转换过程中不联网；正式实现必须支持明确的本地模型目录并禁止运行时静默下载。

### 3.2 页面分类与提取

- 逐页检测有效字符数量、图片覆盖率、字体对象和文字层质量。
- 文本型页面直接解析，不对所有页面盲目 OCR，避免把正确文字识别错。
- 扫描型页面统一使用 PaddleOCR 离线识别，当前版本不接入或测试其他 OCR 引擎。
- 混合型文档逐页选择路径，例如封面扫描、正文原生文本。
- 对旋转页面先校正方向；对低清晰度页面输出明确警告。

### 3.3 布局、语义与纯文本输出

- 按坐标把字符组合为词、行和文本块。
- 根据横向空白、块边界和重叠关系推断单栏、双栏及阅读顺序。
- 对连续页面重复出现的顶部/底部短文本识别为页眉页脚并默认移除。
- 使用字号、字体粗细、编号模式、上下间距和短行特征推断标题。
- 使用项目符号、编号、缩进和行距恢复列表。
- 表格以 `pdfplumber` 检测结果为基础，结合单元格坐标进行校验；无法稳定恢复时降级为制表文本并报告。
- 标题、段落、列表和表格最终渲染为清晰的纯文本；图片本身不输出，只识别其中的文字并统计图片数量。

## 4. 转换报告

PDF 报告在 v1 通用字段上增加：

- PDF 类型：文本型、扫描型或混合型。
- 总页数、成功处理页数、OCR 页数和跳过页数。
- 检测到的标题、段落、列表、表格和图片数量。
- 加密、损坏、超限、低清晰度、异常阅读顺序等警告。
- 表格降级、公式丢失、版面简化、OCR 可能误识别等可能损失。
- 可选的逐页诊断信息，便于定位质量问题，但默认界面只展示摘要。

不应只显示“转换成功”。即使文件生成，只要有明显降级，也要在报告中可见。

## 5. PDF 安全设计

- 校验扩展名、文件头和基本 PDF 结构，拒绝伪装文件。
- 设置单文件大小、批次总量、页数、像素总量和处理时长上限。
- 加密 PDF 默认给出可理解提示；后续可增加用户主动输入密码，不保存密码。
- PDF 解析、页面渲染和 OCR 使用受限子进程并设置超时，失败时终止该文件而不影响整个批次。
- 临时页面图像、OCR 中间文件和提取图片只放在任务临时目录，完成或失败后都清理。
- 输出名称继续避让同名文件，不修改或覆盖原文件。
- 针对畸形对象、巨型页面、超高分辨率图片、对象数量异常和压缩炸弹增加测试。

## 6. HTML 的位置

HTML 放在 PDF 主流程达到验收标准之后，作为 v2.x 的低成本增强：

- 可优先支持 HTML → TXT、Markdown、DOCX，以及现有格式 → HTML。
- 清理脚本、iframe、object、危险 URI 和不可信 raw HTML。
- 不主动下载远程图片、CSS、字体或附件，保持严格离线。
- 不承诺复杂 CSS、交互表单或浏览器像素级布局。

如果 PDF 质量仍未达标，HTML 顺延，不与 PDF 并行扩张范围。

## 7. 暂缓事项

当前里程碑不处理以下事项：

- macOS `.app`、DMG、公证和自动更新。
- Windows 安装包。
- Android 工程、APK/AAB、模拟器和移动端分享。
- HTML 或其他新格式。

这些事项不是永久取消，而是等 PDF → TXT 的识别质量、性能、依赖和交互稳定后再重新排序。开发阶段继续通过 Python 虚拟环境和 Streamlit 本地启动，避免打包问题干扰核心质量验证。

## 9. 分阶段实施

### 阶段 A：PDF 技术验证

1. 建立可公开的 PDF 质量样例集。
2. 验证 PaddlePaddle/PaddleOCR 在 MacBook Air M5 与 Python 3.12 环境中的安装和基本推理。
3. 验证 PP-OCRv5 模型能显式保存到项目外的本地缓存，并在断网状态下正常加载，不发生静默下载。
4. 用少量真实中文样例打通“PDF 页面渲染 → OCR 文字框与置信度 → TXT”的最短流程。
5. 记录单页耗时、内存峰值、旋转页表现和失败信息，确认 `pypdfium2` 等依赖后进入正式实现。

此阶段不是 OCR 引擎横向评测，也不再测试 Tesseract；它只用于排除本机兼容、模型离线加载和端到端接口风险。

**验证结果：** 已通过。详见 [`../validation/2026-09-22-paddleocr-technical-validation.md`](../validation/2026-09-22-paddleocr-technical-validation.md)。正式实现必须固定 PP-OCRv5 模型名称与本地目录、启用页面方向分类，并默认串行处理 OCR 页面。

### 阶段 B：桌面 PDF 核心

1. **已完成：** 安全预检、资源限制和页面分类。
2. **已完成：** 文本型 PDF 原生提取为 TXT，不依赖 Pandoc 或 OCR。
3. **已完成基础链路：** 扫描型、混合型与可疑文字层按页回退到 PaddleOCR PP-OCRv5。
4. **已完成文本页基础版：** 常见双栏、跨栏块和表格语义块恢复。
5. **已完成文本页基础版：** 纯文本渲染、Tab 表格、合并/多行单元格降级规则。
6. **已完成基础接入：** Streamlit 批量界面、进度、PDF 逐页报告和打包下载。

当前 PDF 已加入网页上传和批处理入口。`preflight.py` 和 `classify.py` 负责预检与分类；`extract.py` 提取原生文字层；`quality.py` 拦截替换符、私用区字符和异常重复 glyph；`ocr.py` 使用 PDFium 以 200 DPI 渲染必要页面，并延迟加载显式本地 PP-OCRv5 模型；`pipeline.py` 保持页序、记录原生/OCR/空白页并生成 TXT。

v2.0.0 已完成 PDF 预检/分类/原生提取的短生命周期子进程隔离，以及 PDFium 渲染/PaddleOCR 的文件级子进程隔离。解析默认超时 60 秒；OCR 模型启动限时 30 秒，单页渲染与识别限时 60 秒。文本页已完成稳定双栏、三栏与有框/保守无框表格的坐标恢复，清晰网格的扫描表格也可恢复 Tab 行列。发布时保留跨页/嵌套与旋转密集表格、不规则分栏、复杂表单/公式、图片中文字和子进程绝对内存上限等边界；这些不是未完成的 V2 阻断项。

### 阶段 C：质量加固

1. **真实样例集已扩展到 9 份：** 已覆盖英文三栏、旋转页、有框/无框/跨行表格、简体中文、中英混排、现代/旧式真实扫描件和主动内容警告。
2. 稳定三栏与清华样例的大块相邻页重复已修复；不规则分栏、跨页段落、页眉页脚和局部中英混排继续加固。
3. 有框/无框表格已有基础回归；清晰网格扫描表格与 DPI 对照已验证，旋转、模糊和合并表格继续加固。
4. 畸形、加密、超大和恶意 PDF。
5. 性能基线、内存峰值、取消和临时文件清理。
6. **已完成：** 第二批补充简体中文、中英混排和真实扫描件。
7. **已完成一部分：** 现代简体中文横排扫描、150/300 PPI 扫描表格和 150/200/300 DPI 对照；倾斜、模糊和真实扫描表格仍需补充。
8. README、示例与已知限制。

### 阶段 D：PDF → TXT 版本冻结

**已完成：** 真实样例验收、README、转换报告、演示文件、OpenSpec 同步归档和 `v2.0.0` GitHub Release 均已完成。HTML、macOS 打包和 Android 未进入本版本范围，后续重新评估。

## 10. 测试样例与验收标准

样例集至少包含：

- 中文单栏、双栏和中英文混排的文本型 PDF。
- 有框表格、无框表格、跨页表格。
- 标题、列表、图片、页眉页脚和页码。
- 150 DPI 与 300 DPI 扫描件、倾斜页、旋转页和低清晰度页。
- 文本与扫描页混合的 PDF。
- 加密、损坏、巨型页面和异常对象文件。

验收不只看“能否打开”，还要检查：

- 原文件哈希不变，输出不覆盖输入。
- 正常中文无明显乱码，文本阅读顺序基本正确。
- 标题、段落、列表和简单表格达到人工可接受水平。
- 文本型页面不被无意义 OCR 降质。
- 扫描件明确显示 OCR 状态与风险。
- 单文件失败不影响批次其他文件，临时文件全部清理。
- TXT 使用 UTF-8 编码，可由常见文本编辑器正常打开，段落与列表换行清晰。
- 自动测试、黄金样例比较和人工评分同时通过。

在阶段 A 完成前，不给出脱离样例和硬件实测的准确率承诺。

## 11. 风险与取舍

| 风险 | 处理 |
|---|---|
| PDF 缺少语义，无法通用无损恢复 | 以阅读顺序和文本结构为目标，报告所有降级 |
| OCR 质量受扫描件影响 | 支持预处理、逐页警告和真实样例评分 |
| PaddleOCR 依赖和模型较重 | 先在 MacBook Air M5 实测；模型显式下载到本地，运行时禁止联网 |
| 表格与多栏阅读顺序容易出错 | 独立布局层、代表性样例和人工验收 |
| AGPL 依赖影响 MIT 项目 | 默认不用 PyMuPDF，增加依赖许可证审查 |
| 同时考虑多平台和打包导致失焦 | 当前里程碑只保留 PDF → TXT |

## 12. 已确认决策

已确认：

1. 舍弃 PDF → DOCX，当前只做 PDF → TXT。
2. 暂不考虑 macOS、Windows 或 Android 打包。
3. 暂不实现 Android、HTML 或其他新格式。
4. 扫描页使用 PaddleOCR PP-OCRv5 mobile 检测模型；识别优先使用显式准备的 server 模型，否则使用 mobile 模型。不对 Tesseract 做基准测试，也不将其作为当前版本备用。
5. 模型在安装/初始化阶段显式准备到本地，转换阶段严格离线，不允许静默联网下载。

阶段 C 已补充现代简体中文横排真实扫描件，繁体竖排 OCR 主要列序与跨页重复边栏标题处理已验证；清晰扫描表格和 DPI 对照、联邦公报三栏顺序、清华样例三段跨页重复也已验证。剩余质量目标是倾斜/模糊与真实扫描表格、旋转密集表、跨栏复杂表、表单/公式、旧印刷体错字与独有边栏文字；不扩展新格式或打包范围。

## 13. OpenSpec 规格探索：已确认决策（2026-09-23）

以下仅记录用户在 V1 → V2 增量规格探索中确认的两项决策，尚不是完整或已批准的 V2 规格；在规格确认前不据此修改代码。

1. **旧印刷体识别是 V2 发布前必修项。** 用户要求修好旧印刷体的逐字准确问题，不能把当前样例中的明显错字、漏字简单列为已知限制后发布。可验收的样例范围、逐字准确率或错误容忍度仍待规格阶段明确；不承诺对任意旧印刷体 PDF 达到绝对零错误。
2. **PDF 转换采用整文件成功或失败。** 只要某个必要页面的解析、渲染或 OCR 失败，整份 PDF 标记失败，不提供可能被误认为完整结果的部分 TXT；失败报告说明原因和可定位的页码，同批次其他文件继续处理。

此路线文档保留早期计划与技术取舍；发布判断以 [OpenSpec PDF 主规格](../../openspec/specs/pdf-to-text/spec.md) 和 [已归档任务清单](../../openspec/changes/archive/2026-09-24-add-pdf-to-txt-v2/tasks.md) 为准，不把早期“阶段已完成”字样视为正式验收。最新 [关键页人工记录](../validation/2026-09-24-v2-pdf-manual-closeout.md) 已确认固定五页旧印刷体的主要右到左阅读顺序，并重跑九份真实 PDF 自动样例（9/9）；旋转密集表、跨栏密集表、复杂表单/公式和图片文字仍保留明确限制。
