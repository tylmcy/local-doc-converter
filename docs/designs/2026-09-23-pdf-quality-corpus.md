# PDF 真实质量样例集设计

## 1. 目标与背景

合成 PDF 可以精确验证某条规则，但无法代表真实文档中的字体子集、内容流错序、旋转页、合并表格、脚注、图片与混合文字层。本样例集用于把 PDF → TXT 的“做得好”转成可重复的工程验收，同时保留已知失败作为后续修复目标。

## 2. 范围

本轮包含：

- 建立可版本化的样例清单和人工复核字段。
- 建立显式下载、哈希校验、转换和汇总报告工具。
- 首批引入真实三栏文档、有框/无框/跨行表格、多页文档和旋转密集表。
- 第二批引入简体中文单栏、中英混排多页文档和无文字层的真实扫描件。
- 记录当前输出质量，不为了让样例“全绿”而降低标准。

本轮不包含：

- 把第三方 PDF 二进制文件提交到 GitHub。
- 一次性下载整套 OmniDocBench 或引入其完整评估环境。
- 在样例集建立的同一步骤中修复三栏和旋转表格算法。

## 3. 关键决策

### 3.1 可复现与不再分发分离

仓库仅保存固定 commit 的 HTTPS 地址、原始文件大小、SHA-256、来源页和许可说明。PDF 文件放在 Git 忽略的本地目录。即使上游仓库为 MIT/Apache-2.0，测试 PDF 仍以 `local-only` 处理，避免假设仓库许可必然覆盖其所有外部文档内容。

### 3.2 自动硬验收与人工语义验收分离

自动层只检查完整性、成功状态、页数、最低文字量、表格数和安全警告。阅读顺序、表格语义和 OCR 错字需要渲染原页后人工复核。人工结论保存在清单中，不将当前已知失败误当作自动通过标准。

### 3.3 隐私样例

个人或工作文档使用被忽略的 `local-manifest.json`，不得进入可提交清单。增加公开样例前必须检查许可、个人信息、文档属性和页面内容。

## 4. 文件影响

- `quality/pdf_corpus/manifest.json`：样例元数据与复核结论。
- `quality/pdf_corpus/README.md`：下载、评估、许可与复核说明。
- `src/local_doc_converter/pdf/corpus.py`：清单读取与完整性校验。
- `scripts/download_pdf_corpus.py`：显式联网下载。
- `scripts/evaluate_pdf_corpus.py`：逐件转换和质量汇总。
- `.gitignore`：排除原始 PDF、结果、渲染图和私有清单。

## 5. 失败模式与控制

| 失败模式 | 控制 |
|---|---|
| 上游文件被替换 | 固定 commit URL，严格校验字节数和 SHA-256 |
| 路径穿越 | 清单文件名必须是单个 `.pdf` 基名 |
| 下载中断留下半成品 | 写入 `.part`，校验通过后原子替换 |
| 超大文件 | 下载器单文件上限 50 MB，转换继续使用应用安全限制 |
| 版权或隐私泄露 | 二进制与私有清单默认忽略，公开清单只保存必要元数据 |
| 自动数字看似通过但文本不可读 | 必须保留人工阅读顺序和表格结论 |

## 6. 验证策略

1. 单元测试验证清单、版本固定方式、重复 ID、路径穿越和错误哈希。
2. 对所有首批文件执行下载缓存校验。
3. 执行完整 PDF → TXT 评估，确认原文件哈希不变，并检查 PDF 类型、原生/OCR 页数、文字脚本数量与 OCR 置信度。
4. 渲染代表页并与 TXT 对照，更新人工复核结论。
5. 运行全量 `pytest`、编译检查和 `git diff --check`。

## 7. 已知覆盖缺口

第二批已补充简体中文、中英混排和真实扫描 PDF；第三批加入四页现代简体横排扫描公文。繁体竖排双页扫描的主要列序与跨页重复边栏标题已恢复，高精度识别模型改善了若干旧印刷体词语；错字、漏字和独有边栏文字仍是困难边界。现已增加项目自制的 150/300 PPI 扫描表格与 150/200/300 DPI 对照，验证清晰横竖网格的行列恢复。仍缺倾斜、模糊、真实扫描表格和带完整标准答案的现代中文真实样例；后续可从 OmniDocBench 中挑选少量带阅读顺序和表格标注的页面，但原始数据仍只在本地使用，遵守其“科研使用、不作商业用途”说明。
